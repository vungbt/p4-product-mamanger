# ST-03 — Khởi tạo stay-api, DB và SDK

**Trạng thái:** Chưa bắt đầu · **Ưu tiên:** P0 · **Giai đoạn:** Nền tảng · **Phạm vi:** `apps/stay/api`, `libs/stay/sdk`

**Phụ thuộc:** [ST-01](st-01.md), [ST-02](st-02.md)

## Mục tiêu

Dựng API cho stay với đầy đủ hạ tầng, chưa có nghiệp vụ: đăng nhập, phân quyền, audit, health, OpenAPI và SDK có kiểu.

## Phạm vi

- `apps/stay/api` (`@stay/api`): Express + Sequelize + `@p4/server-core`, cổng mặc định **3011** (tránh 3001 của P4), prefix `/api`.
- Database `p4_stay` trong container Postgres của P4 (dev: `docker-compose.dev.yml`, thêm script tạo DB nếu chưa có). Migration đầy đủ từ đầu, **không dùng `sync()`**.
- Better Auth: `appName: 'Stay'`, `cookiePrefix: 'stay'`, email/password, Google tuỳ chọn qua env. Bảng `users` có `role`.
- Endpoint nền: `GET /health`, `GET /api/me`, `GET /api/me/capabilities` (rules CASL), `/api/auth/*`, `/api/docs` (Scalar).
- OpenAPI generator dùng lại script của P4 (tham số hoá đường dẫn app) → `apps/stay/api/openapi.yaml` → `libs/stay/sdk` (`@stay/sdk`: `./shared`, `./auth`, `./react`) và check "generated up to date".
- Seed tối thiểu: một tài khoản owner cho local (mật khẩu chỉ dùng local, bị chặn ở production như P4).
- Script root: `dev:stay`; env mẫu `.env.example` thêm nhóm `STAY_*` (DB name, port, auth URL/secret).

## Điều kiện nghiệm thu

1. `pnpm --filter @stay/api dev` chạy, `/health` 200, đăng nhập owner qua `/api/auth/sign-in/email` và `/api/me/capabilities` trả rules của owner.
2. Đăng nhập P4 và stay cùng lúc trên localhost không ghi đè cookie của nhau.
3. Route chưa khai báo audit policy thì app không khởi động (giống P4).
4. `openapi.yaml` và SDK sinh được; build SDK fail nếu file sinh ra cũ.
5. Typecheck, lint xanh.
