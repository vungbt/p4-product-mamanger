# FE-21 — Duyệt và kiểm hàng trả

Trạng thái: **Chưa bắt đầu** · Portal: **Admin**

## Mục tiêu

Hoàn thiện duyệt và kiểm hàng trả theo contract API hiện hành. Task chỉ hoàn thành khi màn/luồng đã tích hợp API thật và có kết quả nghiệm thu, không chỉ khi API/SDK đã tồn tại.

## Phụ thuộc

[FE-20](fe-20.md), [FE-38](fe-38.md)

## API và contract

Scalar local: `http://127.0.0.1:3001/api/docs`. Chọn Node.js → Axios để tham khảo; FE dùng `@p4/api-sdk` và hooks resource. Đối chiếu schema hiện hành trước khi triển khai.

- `GET /api/admin/returns`
- `GET /api/returns/{id}`
- `POST /api/returns/{id}/approve`
- `POST /api/returns/{id}/reject`
- `POST /api/returns/{id}/in-transit`
- `POST /api/returns/{id}/receive`
- `POST /api/returns/{id}/inspect`
- `POST /api/returns/{id}/complete`
- `POST /api/orders/{id}/refunds`
- `GET /api/refunds`
- `GET /api/refunds/{id}`
- `POST /api/admin/refunds/{id}/reconcile`
- `POST /api/admin/refunds/{id}/retry`
- `POST /api/admin/refunds/{id}/manual-confirmation`
- `GET /api/files/{id}/download`

Types request/response lấy từ contract sinh trong `@p4/api-sdk/shared`; enum/state nghiệp vụ dùng `@p4/shared`, `@p4/processes/shared`, `@p4/realtime/shared`. Không định nghĩa trùng hoặc ép type để lách schema.

## Ranh giới với task khác

Task này sở hữu return approve/reject/receive/inspect/complete và đánh giá saleable/damaged. Luồng xử lý tiền thuộc FE-50; hiển thị link/status tích hợp thôi.

## Phạm vi và điều kiện nghiệm thu

1. List/detail returns, approve/reject, in-transit/receive/inspect/complete theo API và capability.
2. Kiểm hàng phân biệt saleable/damaged, chỉ restock sau inspection hợp lệ và đúng số lượng.
3. Ảnh bằng chứng private qua authenticated download; link refund và order liên quan, không tự đánh dấu tiền đã hoàn.

## Cách tổ chức và kiểm chứng

- API client, query keys và resource query/mutation hooks nằm trong `libs/api-sdk`; component gọi hook trực tiếp. Hook feature chỉ xử lý state/handler màn hình, không tạo service hoặc hook chuyển tiếp. Props dùng ở đâu định nghĩa ở đó.
- Dùng component/icon/token của `@itclabs/react-ui`, tái sử dụng `libs/blocks`; không dựng lại UI primitives hoặc thêm wrapper/view chỉ để chuyển props.
- Áp dụng [quy ước UI và API](README.md#quy-ước-nghiệm-thu-chung), có loading/empty/error/retry; lỗi field vào field, lỗi chung hiển thị tại form.
- Chạy typecheck/lint/build phù hợp và thao tác luồng thật qua API local. Ghi endpoint, tình huống, kết quả trong phần dưới; không coi mock data là nghiệm thu API.

## Kết quả thực hiện

Chưa thực hiện. Khi hoàn tất, ghi thay đổi, kết quả kiểm chứng và giới hạn còn lại; cập nhật trạng thái cả file này và mục lục.
