# FE-15 — Checkout bằng server quote

Trạng thái: **Chưa bắt đầu** · Portal: **Storefront**

## Mục tiêu

Hoàn thiện checkout bằng server quote theo contract API hiện hành. Task chỉ hoàn thành khi màn/luồng đã tích hợp API thật và có kết quả nghiệm thu, không chỉ khi API/SDK đã tồn tại.

## Phụ thuộc

[FE-12](fe-12.md), [FE-13](fe-13.md), [FE-14](fe-14.md)

## API và contract

Scalar local: `http://127.0.0.1:3001/api/docs`. Chọn Node.js → Axios để tham khảo; FE dùng `@p4/api-sdk` và hooks resource. Đối chiếu schema hiện hành trước khi triển khai.

- `POST /api/checkout/quotes`
- `GET /api/checkout/quotes/{id}`
- `POST /api/shipping/quotes`
- `POST /api/coupons/preview`
- `POST /api/orders`
- `GET /api/addresses`
- `GET /api/shop/config`
- `GET /api/policies/current`

Types request/response lấy từ contract sinh trong `@p4/api-sdk/shared`; enum/state nghiệp vụ dùng `@p4/shared`, `@p4/processes/shared`, `@p4/realtime/shared`. Không định nghĩa trùng hoặc ép type để lách schema.

## Phạm vi và điều kiện nghiệm thu

1. Địa chỉ, phương thức giao và coupon tạo quote server; hiển thị subtotal/discount/shipping/total.
2. Quote hết hạn hoặc giá đổi phải xác nhận lại; submit giữ Idempotency-Key cho một ý định đặt hàng.
3. Đặt đơn gửi `quoteId`, không dùng luồng `items` theo `productId` cũ; gỡ code gọi luồng cũ sau khi chuyển.
4. Hiển thị chính sách từ `GET /api/policies/current` trước khi đặt.
5. Bấm đặt nhiều lần hoặc mạng lỗi rồi retry chỉ tạo một đơn.

## Cách tổ chức và kiểm chứng

- API client, query keys và resource query/mutation hooks nằm trong `libs/api-sdk`; component gọi hook trực tiếp. Hook feature chỉ xử lý state/handler màn hình, không tạo service hoặc hook chuyển tiếp. Props dùng ở đâu định nghĩa ở đó.
- Dùng component/icon/token của `@itclabs/react-ui`, tái sử dụng `libs/blocks`; không dựng lại UI primitives hoặc thêm wrapper/view chỉ để chuyển props.
- Áp dụng [quy ước UI và API](README.md#quy-ước-nghiệm-thu-chung), có loading/empty/error/retry; lỗi field vào field, lỗi chung hiển thị tại form.
- Chạy typecheck/lint/build phù hợp và thao tác luồng thật qua API local. Ghi endpoint, tình huống, kết quả trong phần dưới; không coi mock data là nghiệm thu API.
