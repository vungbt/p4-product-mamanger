# FE-21 — Duyệt, nhận hàng trả và hoàn tiền

Trạng thái: **Chưa bắt đầu** · Portal: **Admin**

## Mục tiêu

Hoàn thiện luồng duyệt, nhận hàng trả và hoàn tiền với API local đã triển khai. Đây là task frontend độc lập; tạo file task không có nghĩa màn hình đã hoàn thành.

## Phụ thuộc

[FE-20](fe-20.md), [FE-38](fe-38.md)

## API và contract

Scalar local: `http://127.0.0.1:3001/api/docs`. Chọn Node.js → Axios để tham khảo; FE dùng service và API client hiện có. Đối chiếu schema hiện hành trước khi triển khai.

- `GET /api/admin/returns`
- `GET /api/returns/{id}`
- `POST /api/returns/{id}/approve`
- `POST /api/returns/{id}/reject`
- `POST /api/returns/{id}/in-transit`
- `POST /api/returns/{id}/receive`
- `POST /api/returns/{id}/inspect`
- `POST /api/returns/{id}/complete`
- `POST /api/orders/{id}/refunds`
- `GET /api/refunds`
- `GET /api/refunds/{id}`
- `POST /api/admin/refunds/{id}/reconcile`
- `POST /api/admin/refunds/{id}/retry`
- `POST /api/admin/refunds/{id}/manual-confirmation`
- `GET /api/files/{id}/download`

Types lấy từ `@p4/shared`, `@p4/processes/shared`, `@p4/realtime/shared`; không tự định nghĩa lại enum/state phía FE.

## Phạm vi và điều kiện nghiệm thu

1. Approve/reject/receive/inspect phân biệt saleable và damaged; restock chỉ sau inspection hợp lệ.
2. Refund pending/processing/failed/succeeded; retry/reconcile và manual COD confirmation có reference, không giả đã hoàn.
3. Xem ảnh bằng chứng riêng tư qua `GET /api/files/{id}/download`.
4. Refund chưa rõ kết quả phải reconcile trước; chỉ retry khi provider đã xác nhận thất bại.
5. Hoàn tiền thủ công cần reference và không hiển thị đã hoàn trước khi xác nhận.

## Cách tổ chức và kiểm chứng

- HTTP service trong `apps/web/src/services`; state/query/mutation/handler trong hook feature; component trình bày cùng feature, props dùng ở đâu định nghĩa ở đó.
- Dùng component/icon/token của `@itclabs/react-ui`, tái sử dụng `libs/blocks`; không dựng lại UI primitives hoặc thêm wrapper/view chỉ để chuyển props.
- Áp dụng [quy ước UI và API](README.md#quy-ước-nghiệm-thu-chung), có loading/empty/error/retry; lỗi field vào field, lỗi chung hiển thị tại form.
- Chạy typecheck/lint/build phù hợp và thao tác luồng thật qua API local. Ghi endpoint, tình huống, kết quả trong phần dưới; không coi mock data là nghiệm thu API.

## Kết quả thực hiện
