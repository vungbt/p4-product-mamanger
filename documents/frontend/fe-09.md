# FE-09 — Profile, địa chỉ và quản lý phiên

Trạng thái: **Chưa bắt đầu** · Portal: **Chung**

## Mục tiêu

Hoàn thiện luồng profile, địa chỉ và quản lý phiên với API local đã triển khai. Đây là task frontend độc lập; tạo file task không có nghĩa màn hình đã hoàn thành.

## Phụ thuộc

[FE-08](fe-08.md), [FE-38](fe-38.md), [FE-40](fe-40.md)

## API và contract

Scalar local: `http://127.0.0.1:3001/api/docs`. Chọn Node.js → Axios để tham khảo; FE dùng service và API client hiện có. Đối chiếu schema hiện hành trước khi triển khai.

- `GET /api/me/profile`
- `PATCH /api/me/profile`
- `GET /api/me/preferences`
- `PATCH /api/me/preferences`
- `POST /api/me/email-change-requests`
- `POST /api/me/email-changes/confirm`
- `GET /api/me/sessions`
- `DELETE /api/me/sessions/{id}`
- `POST /api/me/sessions/revoke-others`
- `PATCH /api/auth/me`
- `PATCH /api/auth/password`
- `GET /api/addresses`
- `POST /api/addresses`
- `PUT /api/addresses/{id}`
- `DELETE /api/addresses/{id}`
- `PATCH /api/addresses/{id}/default`

Types lấy từ `@p4/shared`, `@p4/processes/shared`, `@p4/realtime/shared`; không tự định nghĩa lại enum/state phía FE.

## Phạm vi và điều kiện nghiệm thu

1. Profile/avatar, preferences, đổi email/mật khẩu và phiên đăng nhập dùng API owner.
2. Địa chỉ mặc định duy nhất; stale version 409 cho phép tải lại; đổi mật khẩu yêu cầu đăng nhập lại.
3. Có màn nhận link xác nhận đổi email từ `POST /api/me/email-changes/confirm`.
4. Avatar dùng upload chung ở FE-38.
5. Thu hồi phiên hiện tại đưa về login; thu hồi phiên khác cập nhật danh sách ngay.

## Cách tổ chức và kiểm chứng

- HTTP service trong `apps/web/src/services`; state/query/mutation/handler trong hook feature; component trình bày cùng feature, props dùng ở đâu định nghĩa ở đó.
- Dùng component/icon/token của `@itclabs/react-ui`, tái sử dụng `libs/blocks`; không dựng lại UI primitives hoặc thêm wrapper/view chỉ để chuyển props.
- Áp dụng [quy ước UI và API](README.md#quy-ước-nghiệm-thu-chung), có loading/empty/error/retry; lỗi field vào field, lỗi chung hiển thị tại form.
- Chạy typecheck/lint/build phù hợp và thao tác luồng thật qua API local. Ghi endpoint, tình huống, kết quả trong phần dưới; không coi mock data là nghiệm thu API.
