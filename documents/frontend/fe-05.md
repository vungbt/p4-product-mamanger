# FE-05 — SKU và biến thể sản phẩm

Trạng thái: **Chưa bắt đầu** · Portal: **Admin**

## Mục tiêu

Hoàn thiện quản lý SKU theo size/màu của sản phẩm với API local đã triển khai.

## Phụ thuộc

[FE-04](fe-04.md), [FE-39](fe-39.md)

## API và contract

Scalar local: `http://127.0.0.1:3001/api/docs`. Chọn Node.js → Axios để tham khảo; FE dùng service và API client hiện có. Đối chiếu schema hiện hành trước khi triển khai.

- `GET /api/admin/products/{id}/variants`
- `POST /api/products/{id}/variants`
- `PATCH /api/products/{id}/variants/{variantId}`
- `PATCH /api/products/{id}/variants/{variantId}/images`
- `GET /api/admin/variants`

Types lấy từ `@p4/shared`, `@p4/processes/shared`, `@p4/realtime/shared`; không tự định nghĩa lại enum/state phía FE.

## Phạm vi và điều kiện nghiệm thu

1. Mỗi size/màu có SKU, giá, ảnh và trạng thái riêng; không sửa định danh SKU đã bán.
2. Sửa SKU không gửi `stock`, `onHand`, `reserved`: tồn kho chỉ đổi qua FE-42.
3. SKU trùng hiển thị lỗi đúng field; sản phẩm phải còn SKU hợp lệ thì mới publish được theo kết quả API.
4. Danh sách `GET /api/admin/variants` tìm và lọc phía server, dẫn về đúng sản phẩm.

## Cách tổ chức và kiểm chứng

- HTTP service trong `apps/web/src/services`; state/query/mutation/handler trong hook feature; component trình bày cùng feature, props dùng ở đâu định nghĩa ở đó.
- Dùng component/icon/token của `@itclabs/react-ui`, tái sử dụng `libs/blocks`; không dựng lại UI primitives hoặc thêm wrapper/view chỉ để chuyển props.
- Áp dụng [quy ước UI và API](README.md#quy-ước-nghiệm-thu-chung), có loading/empty/error/retry; lỗi field vào field, lỗi chung hiển thị tại form.
- Chạy typecheck/lint/build phù hợp và thao tác luồng thật qua API local. Ghi endpoint, tình huống, kết quả trong phần dưới; không coi mock data là nghiệm thu API.
