# FE-38 — Upload dùng chung qua ticket

Trạng thái: **Chưa bắt đầu** · Portal: **Chung**

## Mục tiêu

Dựng luồng upload một và nhiều file qua ticket theo owner/purpose để các màn avatar, sản phẩm, review, CMS, banner, trả hàng và ticket hỗ trợ dùng lại.

## Phụ thuộc

[FE-37](fe-37.md), [FE-10](fe-10.md)

## API và contract

Scalar local: `http://127.0.0.1:3001/api/docs`. Chọn Node.js → Axios để tham khảo; FE dùng service và API client hiện có. Đối chiếu schema hiện hành trước khi triển khai.

- `POST /api/files/uploads`
- `POST /api/files/uploads/{id}/complete`
- `GET /api/files/uploads/{id}`
- `POST /api/files/uploads/batch`
- `POST /api/files/uploads/batch/complete`
- `GET /api/files/{id}/download`
- `DELETE /api/files/{id}`
- `GET /api/files/sign-upload-url`
- `GET /api/files/sign-upload-urls`

Types lấy từ `@p4/shared`, `@p4/processes/shared`, `@p4/realtime/shared`; không tự định nghĩa lại enum/state phía FE.

## Phạm vi và điều kiện nghiệm thu

1. Một component/hook dùng chung cho upload một file và nhiều file, nhận `purpose` theo từng màn.
2. Hiển thị tiến độ và kết quả từng file; file lỗi không ảnh hưởng các file còn lại, retry không tạo file trùng.
3. Chỉ dùng file sau khi `complete` xác nhận; không gắn file chưa verify vào dữ liệu nghiệp vụ.
4. File riêng tư tải qua `GET /api/files/{id}/download` có xác thực, không dùng URL public tĩnh.
5. Chuyển các chỗ đang dùng `useUploadFile` (ký URL qua `/files/sign-upload-url`) sang ticket rồi ghi rõ phần nào còn dùng luồng cũ.

## Cách tổ chức và kiểm chứng

- HTTP service trong `apps/web/src/services`; state/query/mutation/handler trong hook feature; component trình bày cùng feature, props dùng ở đâu định nghĩa ở đó.
- Dùng component/icon/token của `@itclabs/react-ui`, tái sử dụng `libs/blocks`; không dựng lại UI primitives hoặc thêm wrapper/view chỉ để chuyển props.
- Áp dụng [quy ước UI và API](README.md#quy-ước-nghiệm-thu-chung), có loading/empty/error/retry; lỗi field vào field, lỗi chung hiển thị tại form.
- Chạy typecheck/lint/build phù hợp và thao tác luồng thật qua API local. Ghi endpoint, tình huống, kết quả trong phần dưới; không coi mock data là nghiệm thu API.

## Kết quả thực hiện

Chưa thực hiện. Khi hoàn tất, ghi thay đổi, kết quả kiểm chứng và giới hạn còn lại; cập nhật trạng thái cả file này và mục lục.
