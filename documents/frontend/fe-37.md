# FE-37 — Lớp gọi API và xử lý lỗi dùng chung

Trạng thái: **Đã có một phần — cần hoàn thiện/nghiệm thu** · Portal: **Chung**

## Mục tiêu

Hoàn thiện lớp gọi api và xử lý lỗi dùng chung theo contract API hiện hành. Task chỉ hoàn thành khi màn/luồng đã tích hợp API thật và có kết quả nghiệm thu, không chỉ khi API/SDK đã tồn tại.

## Phụ thuộc

[FE-01](fe-01.md)

## API và contract

Scalar local: `http://127.0.0.1:3001/api/docs`. Chọn Node.js → Axios để tham khảo; FE dùng `@p4/api-sdk` và hooks resource. Đối chiếu schema hiện hành trước khi triển khai.

Task này không thêm endpoint mới; áp dụng cho mọi nhóm API.

Types request/response lấy từ contract sinh trong `@p4/api-sdk/shared`; enum/state nghiệp vụ dùng `@p4/shared`, `@p4/processes/shared`, `@p4/realtime/shared`. Không định nghĩa trùng hoặc ép type để lách schema.

## Phạm vi và điều kiện nghiệm thu

1. `@p4/api-sdk` đã build và category hooks đã ghép. Bổ sung resource API/hooks tại SDK theo từng task; dùng chung QueryClient từ ApiQueryProvider và xóa wrapper không có logic. App không phải tự `unwrap`/invalidate cho từng mutation.
2. Helper `Idempotency-Key`: giữ nguyên key khi retry cùng một thao tác, tạo key mới cho ý định mới.
3. Xử lý thống nhất: lỗi 400 map `extensions` vào từng field của form; 401, 403, 404, 409 và 429 (theo `Retry-After`) có hiển thị rõ ràng.
4. Lỗi 409 version conflict có cách tải lại dữ liệu mới và không làm mất nội dung đang nhập.
5. Thông báo lỗi chung có kèm `X-Request-Id` để đối chiếu log.

## Cách tổ chức và kiểm chứng

- API client, query keys và resource query/mutation hooks nằm trong `libs/api-sdk`; component gọi hook trực tiếp. Hook feature chỉ xử lý state/handler màn hình, không tạo service hoặc hook chuyển tiếp. Props dùng ở đâu định nghĩa ở đó.
- Dùng component/icon/token của `@itclabs/react-ui`, tái sử dụng `libs/blocks`; không dựng lại UI primitives hoặc thêm wrapper/view chỉ để chuyển props.
- Áp dụng [quy ước UI và API](README.md#quy-ước-nghiệm-thu-chung), có loading/empty/error/retry; lỗi field vào field, lỗi chung hiển thị tại form.
- Chạy typecheck/lint/build phù hợp và thao tác luồng thật qua API local. Ghi endpoint, tình huống, kết quả trong phần dưới; không coi mock data là nghiệm thu API.

## Kết quả thực hiện

SDK generated client, category hooks, cache invalidation và field errors đã có từ PR #36. Hooks các resource khác và chuẩn hóa idempotency/version/request ID còn phải làm theo kế hoạch. Khi hoàn tất, ghi thay đổi, kết quả kiểm chứng và giới hạn còn lại; cập nhật trạng thái cả file này và mục lục.
