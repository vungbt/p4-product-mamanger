# FE-18 — Vận hành nhiều kiện và COD

Trạng thái: **Chưa bắt đầu** · Portal: **Admin**

## Mục tiêu

Hoàn thiện luồng vận hành nhiều kiện và cod với API local đã triển khai. Đây là task frontend độc lập; tạo file task không có nghĩa màn hình đã hoàn thành.

## Phụ thuộc

[FE-17](fe-17.md)

## API và contract

Scalar local: `http://127.0.0.1:3001/api/docs`. Chọn Node.js → Axios để tham khảo; FE dùng service và API client hiện có. Đối chiếu schema hiện hành trước khi triển khai.

- `GET /api/orders/{id}/shipments`
- `POST /api/orders/{id}/shipments`
- `POST /api/shipments/{id}/pack`
- `POST /api/shipments/{id}/ready`
- `POST /api/shipments/{id}/handover`
- `POST /api/shipments/{id}/out-for-delivery`
- `POST /api/shipments/{id}/deliver`
- `POST /api/shipments/{id}/fail`
- `POST /api/shipments/{id}/return`
- `POST /api/shipments/{id}/lose`
- `POST /api/shipments/{id}/cancel`
- `GET /api/shipments/{id}/events`
- `POST /api/admin/payments/{id}/cod-collection`
- `POST /api/admin/payments/{id}/reconcile`

Types lấy từ `@p4/shared`, `@p4/processes/shared`, `@p4/realtime/shared`; không tự định nghĩa lại enum/state phía FE.

## Phạm vi và điều kiện nghiệm thu

1. Phân bổ số lượng vào nhiều kiện, pack/ready/handover/deliver/fail/return/lose theo trạng thái.
2. Thu COD là thao tác riêng có reference/amount; delivered không tự đồng nghĩa đã thu tiền.
3. Không chia vượt số lượng đã đặt; lỗi từ API hiển thị đúng dòng.
4. Gọi lặp một action không bàn giao hai lần; action không hợp lệ theo trạng thái bị ẩn hoặc disabled kèm lý do.

## Cách tổ chức và kiểm chứng

- HTTP service trong `apps/web/src/services`; state/query/mutation/handler trong hook feature; component trình bày cùng feature, props dùng ở đâu định nghĩa ở đó.
- Dùng component/icon/token của `@itclabs/react-ui`, tái sử dụng `libs/blocks`; không dựng lại UI primitives hoặc thêm wrapper/view chỉ để chuyển props.
- Áp dụng [quy ước UI và API](README.md#quy-ước-nghiệm-thu-chung), có loading/empty/error/retry; lỗi field vào field, lỗi chung hiển thị tại form.
- Chạy typecheck/lint/build phù hợp và thao tác luồng thật qua API local. Ghi endpoint, tình huống, kết quả trong phần dưới; không coi mock data là nghiệm thu API.
